# 使用说明

## 基本流程

1. **选模式**：强化、重抽或联合，区别见 [README](../README.md#功能)。
2. **选评分**：先选评分体系，再选角色预设和变体（命座、主词条或模式）。
3. **设目标**：填写目标总分，即评分工具里显示的总分，主词条分已包含在内。需要时可以展开面板，微调词条权重和资源的相对价值。
4. **点击「求解策略」**：根据当前评分、目标和资源价值计算策略。
5. **填写词条**：录入已经开出的副词条，数值从下拉框中选择游戏里的实际档位，建议会随之更新。

求解完成后，修改词条会立即得到新建议，无需再次求解；清空词条即可继续处理下一个胚子。**修改评分、目标或资源价值后，需要重新点击「求解策略」。**

## 三种模式

### 强化

录入 0–5 条已开出的词条，界面建议继续强化还是放弃，并显示：

- 当前声骸的达标概率：始终按建议操作时，这件声骸在被放弃之前达标的概率；
- 平均每件成品的资源消耗：从新胚子算起，已包含失败的尝试、分解返还，以及成品升满所需的资源。

### 重抽

录入一件满五条的声骸，界面给出推荐锁法、预计还需多少频整器，以及每种锁法**这一次**重抽就达标的概率。

重抽出结果后，把候选声骸填入候选栏，界面会比较两者的后续期望消耗：

- 接受候选：候选成为当前声骸，界面给出下一步的锁法；
- 保留原声骸：清空候选，继续重抽。

重抽模式的资源统计从当前声骸算起，只包含之后的频整器消耗。

### 联合

和强化模式一样逐条录入词条，但满词条后可能建议保留、重抽或放弃。联合模式只判断“值不值得开始重抽”，不显示具体锁法和候选比较。建议重抽时，点击「转到重抽策略」，当前声骸、评分和目标会自动带入重抽模式。

结果中的“保留概率”指按策略执行时这件声骸不被放弃的概率，包括转入重抽后最终达标的情况。

## 资源相对价值

资源价值表示各类资源之间的换算比例，例如频整器设为 1000，表示一个频整器值一千个调谐器。计算器最小化的是按此加权后的**期望**总消耗，这个数值不是库存上限，也不保证单次实际花费不超过某个数。

经验以特级密音筒为单位，1 个 = 5000 经验，分解返还按实测表计算。

## 预设

- 预设列表只显示当前评分体系的角色，最新实装的角色排在前面。
- 顶部的全局搜索覆盖所有评分体系和自定义预设，支持中英文角色名；选中其他体系的预设时会自动切换评分体系。
- 当前提供线性、固定、Wuwa Echo Tool、漂泊者强化助手、XutheringWavesUID 五套评分。
- 自定义预设和最近一次的配置保存在当前浏览器或桌面应用中。可以导出为 JSON，再在另一端导入；导入同名、同评分体系的预设会覆盖原有的预设。

**从旧版桌面应用迁移**：旧版的 `scorer-presets/*.json` 不会自动迁移，原文件也保持不动。先切换到对应的评分体系，再用「导入预设」读取这些文件即可。

## 角色数据更新

- **网页版**：角色和权重由服务器统一更新，刷新页面即可获得最新数据。
- **桌面版**：在「角色数据」中在线更新，或导入下载好的数据文件。

数据更新不会改动当前正在使用的配置；需要新权重时，重新选择一次预设即可。详见[角色数据包](../data/README.md)。

## 桌面版 OCR

Windows x64 桌面版安装可选内置组件后，可选择「内置识别」，点击「开启 OCR 自动填入」，自动识别简体中文、16:9 游戏客户区中装备页右侧或强化页左侧的副词条。多个游戏窗口时，先停止识别并选择目标。识别范围、组件准备与构建见[本机 OCR](本机OCR.md)。

其他平台或未安装组件时默认使用「外部 ok-ww」模式，在本机 UDP 9999 端口接收 [ok-ww](https://github.com/ok-oldking/ok-wuthering-waves) 识别出的词条并自动填入。需要先把 `apps/ocr/` 中的任务加入 ok-ww，消息格式见 [apps/ocr/message.md](../apps/ocr/message.md)。内置与外部识别二选一，网页版不支持 OCR。

## 网页版的排队与配额

网页版的计算在服务器上进行。同一时间只计算一份新策略，其他请求需要排队，界面会显示排队状态；已经算过的配置会直接复用缓存。

为防止滥用，每个 IP 每小时新建策略的次数有上限。超出上限时，界面会提示需要等待多久。拥有访问密钥的用户可以在右上角「访问密钥」中输入密钥，不受个人配额限制。密钥只保存在当前标签页中。

## 其他

- 右上角可以切换中文 / EN，切换后当前的配置和结果都会保留。
- 界面中的游戏术语依据 Wiki 校对，见[术语对照](../apps/web/TERMINOLOGY.md)。
- 为限制计算规模，最高五条副词条的内部评分合计不能超过 20000。超出时会报错，可以降低归一化满分或固定权重。
